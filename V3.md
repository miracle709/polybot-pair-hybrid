# V3 unified pair-directional portfolio engine

V3 is implemented to the **shadow-ready** milestone. It is not a claim of
profitability and it is not an active directional trader. V2 remains the only
exchange execution path in this development pass.

## Versions and activation state

- V1: unrestricted two-sided accumulation; retained only as characterization
  and regression history.
- V2: active finite FIFO pair-cycle engine with marginal complement economics.
- V3 scaffold: exact two-terminal portfolio math, action-specific fees, causal
  signals, probability interfaces, unified candidates, pair interaction, risk
  constraints, research tooling, and hazard telemetry.
- V3 shadow: enabled by `V3_ENABLED=1` with `V3_SHADOW_ONLY=1`. It records a
  hypothetical decision next to the unchanged V2 rung reconciliation.
- V3 active: not authorized by this milestone. No V3 candidate is routed to
  `OrderManager` or an exchange adapter.

Default configuration is V2-compatible:

```text
V3_ENABLED=0
V3_SHADOW_ONLY=1
DIRECTIONAL_ENABLED=0
DIRECTIONAL_MAKER_ENABLED=0
DIRECTIONAL_TAKER_ENABLED=0
ALLOW_MODEL_TO_DEFER_PAIR_COMPLETION=0
```

## Authoritative mathematics

For total UP shares `Q_U`, DOWN shares `Q_D`, acquisition cost `C`, and
historical/expected fees `F`:

```text
PnL_UP       = Q_U - C - F
PnL_DOWN     = Q_D - C - F
WorstCasePnL = min(PnL_UP, PnL_DOWN)
```

For a marginal UP buy of `q` shares at `p` with marginal fee `φ`:

```text
ΔPnL_UP outcome   = q(1-p) - φ
ΔPnL_DOWN outcome = -qp - φ
EV_UP             = q(π-p) - φ
RobustEV_UP       = q(lower-p) - φ - executionReserve
```

For DOWN:

```text
EV_DOWN       = q((1-π)-p) - φ
RobustEV_DOWN = q((1-upper)-p) - φ - executionReserve
```

For an actual complete set:

```text
PairEV = q(1-p_UP-p_DOWN) - executionCosts
```

Historical fees are part of the authoritative portfolio once. Only the new
action's fee enters marginal EV. Maker fees use notional bps supplied by the
caller. Crypto taker fees use `q × feeRate × p × (1-p)`. A separate builder
fee, if configured, is applied once to action notional.

Directional evaluation currently uses the configured static maker/taker
reserve. `EmpiricalExecutionReserveModel` can consume an offline, no-look-ahead
conditional adverse-markout quantile artifact bucketed by execution type,
round regime, volatility, and spread. It falls back to the static reserve when
validation or sample coverage is insufficient; existing LIVE maker markouts
remain the measurement source.

## Causality and source policy

Every buffered observation has a publisher time and a local arrival time. At
decision time `t`, it is usable only when both are `<= t`. A horizon return
uses the latest observation at `t` and a historical observation with timestamp
`<= t-h`; the implementation never chooses a future observation because it is
closer.

The feature engine computes 1/3/5/10-second BTC and ex-own CLOB log returns,
raw and log settlement gap, an independent 30-second reference TWAP gap,
realized volatility, remaining volatility, spread, depth, and imbalance. The
legacy `±1 bp` direction is telemetry only.

`SourceQuality` is `AUTHORITATIVE`, `APPROXIMATE`, or `UNTRUSTED`. Ambiguous
names are not promoted. In particular, `chainlink_onchain_approx` and exchange
spot are not the exact Chainlink Data Streams settlement source. Directional
authorization requires both the price-to-beat and current settlement reference
to be authoritative. Missing or stale data invalidates the snapshot but never
halts V2.

Public midpoint features subtract this process's resting bid quantities,
including the complementary-token representation of asks. If subtraction is
inconsistent with the public level, `ownQuoteContaminated=true` and the signal
is invalid.

## Probability models

`StructuralProbabilityModel` is a zero-drift short-horizon diffusion benchmark:

```text
z = [ln(S/K) - 0.5 σ²τ] / [σ sqrt(τ)]
pUp = Φ(z)
```

Volatility is in log-return units per square-root second and `τ` is seconds.
`τ=0`, `σ=0`, and `S=K` are deterministic. The model deliberately returns the
maximally conservative interval `[0,1]` and `calibrated=false`, so it cannot
authorize directional capital.

`MarketResidualLogisticModel` loads an offline artifact and uses:

```text
logit(pUp) = logit(clamped causal UP midpoint) + intercept + βᵀX
```

It treats correlated features jointly. It never multiplies signal
probabilities as if they were independent. Calibration is accepted only from
a chronological walk-forward artifact with a supported method, sufficient
sample count, and an empirical uncertainty bin.

## Unified candidates and selection

The common action language includes `NO_ACTION`, `PAIR_OPEN`, `PAIR_COMPLETE`,
directional maker/taker actions for both legs, `RISK_REDUCTION`, and
`CANCEL_STALE`. Non-null candidates carry exact after-state PnL, point and
robust EV, expected fee/reserve, capital, risk delta, probability provenance,
execution type, eligibility reasons, and pair interaction.

Before every directional candidate, a pure FIFO preview inspects unmatched
opposite lots. Any resulting physical pair above `PAIR_HARD_MAX_MILS` makes the
candidate ineligible regardless of its `DIRECTIONAL` intent. Intent remains
provenance and cannot alter physical matching.

Eligible directional sizes are a venue-legal discrete grid. Constraints include
fresh/authoritative inputs, a valid calibrated model, minimum robust EV,
`MAX_DIRECTIONAL_LOSS_USD`, `MAX_DIRECTIONAL_SHARES`, round notional, pair hard
maximum, depth, and configured round regimes. V2-economic pair completion has
priority while `ALLOW_MODEL_TO_DEFER_PAIR_COMPLETION=0`. If nothing has robust
positive value, `NO_ACTION` is selected.

## Telemetry and research

The non-blocking activity recorder accepts `signal_snapshot`,
`probability_prediction`, `action_candidates`, `action_selected`,
`action_rejected`, `v3_shadow_decision`, and
`pair_completion_observation`. First-leg observations track causal market
context, complement price path, completion time, pair price, configured
horizons, and eventual outcome. The default completion model is explicitly
unvalidated and cannot alter V2.

Run the offline pipeline with:

```text
npm run research:v3 -- logs/activity-....jsonl \
  --dataset research-rows.json \
  --report walk-forward-report.json \
  --artifact model-artifact.json
```

The pipeline rejects feature rows containing a source timestamp after decision
time, joins eventual labels and execution observations separately, and performs
strict past-rounds-to-next-rounds evaluation. It reports Brier score, log loss,
calibration error/curve, sample count, net directional value after observed
costs, and simulated max drawdown, with market, structural, legacy-unanimous,
and no-action baselines.

Remaining work before any active directional mode includes representative data
collection, out-of-sample calibration stability, provider/source verification,
maker fill and markout modeling, pair-completion hazard validation, capacity
limits, small paper/canary operation, and a separate approval for taker risk.
